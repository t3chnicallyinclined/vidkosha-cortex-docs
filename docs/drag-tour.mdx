DRAG is a network that keeps knowledge fresh and searchable — a “living library” run by operators.

## What gets built first

- Wikipedia/Wikidata
- Open research indexes/feeds (where terms allow)
- Standards/RFCs and open technical docs
- Public datasets

## New use case: agents + inference endpoints = operator-deployed workflows

The point of these examples isn’t “YouTube specifically.” It’s that operators can build and deploy **practical inference + tool workflows** (as APIs) on top of DRAG’s freshness + packs + routing.

A reliable end-to-end pipeline an operator can host and sell:

- Prompt → **Researcher agent** gathers sources and fresh context from packs
- Research → **Script writer** produces outline + narration
- Script → **Voice agent** generates voiceover
- Script → **Video generator** creates 10–30s clips
- **Stitching** assembles a cohesive video with captions/metadata

These become **metered endpoints** (e.g. “generate highlights”, “generate chapters”, “produce clip plan”, “produce metadata pack”) that customers call via a stable API.

## Example (content): YouTube/podcast semantic archive packs

Continuously ingest transcripts and metadata for a curated set of channels/topics, embed them, and serve semantic search with grounded quotes.

## Example (content): full SEO package automation for long podcasts

Send a long-form video (e.g., a 3-hour podcast) and automatically generate a complete “YouTube-ready” SEO pack:

- **SEO title** options and positioning variants
- **Rich description** (chapters/timestamps, links, CTAs)
- **Trending hashtags** and keyword clusters
- **Highlight reel plan** and suggested clip boundaries
- **Shorts/clips** (10–30s segments) with suggested hooks
- **Thumbnail suggestions** (concepts + text overlays)

This is a natural multi-agent pipeline: transcript → topic map → highlights → copywriting → packaging.

If you don’t care about content, swap in a different vertical: compliance review, support-ticket triage, research brief generation, incident postmortems, market monitoring, and more. The *shape* stays the same: ingest → pack → retrieve → infer/tool → serve as a paid API.

## New use case: freshness window + paid archival retrieval

Use JetStream retention (e.g. 7 days) as the default “freshness window”: everything older expires unless someone pays to keep it.

- Hot path: fast, cheap retrieval across the last $T$ days
- Cold path: archived packs stored by storage operators and served on-demand for a fee
