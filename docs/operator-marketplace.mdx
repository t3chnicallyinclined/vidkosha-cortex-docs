This page describes the **payout accounting loop**: usage events get aggregated into payout batches and settled.

If the network can’t measure work, it can’t pay for work — and you don’t get a real operator ecosystem.

## v1 simplification

In v1, Vidkosha Cortex runs **first-party operators only**.
We intentionally defer open-marketplace mechanics (third-party discovery, bidding, escrow/disputes) until the network has real volume and adversarial pressure.

Stable-first posture:
- Customers pay in fiat or stablecoins (unit-of-account is USD/USDC).
- Operators are paid in **USDC** on an epoch schedule (weekly recommended).

Canonical tokenomics: [VKC tokenomics (v1)](/docs/vkc-tokenomics).

## Accounting primitives

Even without an open marketplace, the network needs a boring, auditable accounting spine:

- `usage_event`: append-only record of billable work (who did what, units, SLO tier, price quote vs actual).
- `payout_batch`: epoch aggregation of usage events into “who gets paid how much”.
- `treasury_policy`: guardrails for reserves, payout pool size, and optional POL budget.

Economics and token model are centralized in: [VKC tokenomics (v1)](/docs/vkc-tokenomics).

## Payout lifecycle (weekly)

1. Request executes as one or more missions.
2. Each mission emits a `usage_event`.
3. At epoch close, `usage_event`s aggregate into a `payout_batch`.
4. Treasury settles the batch in **USDC** (v1 default).
5. Optional: publish a hash-only checkpoint of the batch root (later).

## What gets metered

- Retrieval and storage (pack serving)
- Embeddings (vector generation)
- Inference (optional tiers)
- **Tool/MCP execution** (workflow steps like transforms, render, stitching)

In practice, these show up to users as **paid API endpoints** (“run this workflow”, “generate this artifact”, “answer with citations”), backed by operators who commit to SLO + price.

Reference:

- [Packs (archival packs)](/docs/packs)

Metering needs to be boring and machine-verifiable:

- work unit ID (idempotency)
- operator identity
- service + recipe/model/version pins
- bytes/records/seconds (depending on service)
- SLO tier (latency/availability)
- price quote vs actual usage

## Deferred: open marketplace mechanics

If/when third-party operators are enabled, additional surfaces can be added (catalog discovery, bidding, escrow/disputes, and stronger enforcement). v1 keeps these out of scope to reduce complexity.

## Storage operator incentive: 7-day WAL + paid archives

Use JetStream retention (e.g. 7d) as the baseline freshness window:

- **Hot path** (≤ $T$): cheap and fast, bounded storage cost.
- **Cold path** (> $T$): storage operators compete to retain archival packs and charge for retrieval.

This turns “infinite retention” from a hidden network cost into an explicit market.
